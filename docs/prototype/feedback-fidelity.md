# 反馈列表的源码复用原型

本入口使用客服后台实际的 `src/pages/workOrder/workOrderList` 及其直接依赖，生成本地可运行的 HTML。它对应「工单管理 → 反馈列表」，路由为 `#/workOrder/workOrderList`。原页面的表格、查询表单、详情、聊天记录、指派、批量回复和动态表单通过真实组件执行；页面外壳单独实现，避免启动原应用的路由发现、登录和网络初始化。

本次扫描后用户已明确选择「仅 PC 端，按原系统还原」。原系统支持范围与本次选择须分别记录；这里的 `--device desktop` 只记录调用选择，不代替用户确认。本入口拒绝移动端及双端参数，不生成移动适配。其他目标项目必须重新扫描并询问端型，不能直接沿用本项目的选择。

## 使用命令

在仓库根目录使用 Node.js 22.18+ 和已安装的仓库依赖。原后台源码目录及其所需依赖也必须已经可用；该命令不安装依赖、不启动原系统、不扫描其他项目。

```powershell
node prototype/feedback-fidelity.mjs --help
node prototype/feedback-fidelity.mjs --source 'C:\path\to\cs_admin-client' --device desktop --out prototype-output/feedback-source-pc-new
```

将示例的 `--source` 换为实际源码根目录。输出父目录须已存在，输出目录本身必须不存在；需要时先在本仓库内创建 `prototype-output`。成功后用浏览器打开新目录内的 `index.html`。命令只输出两个文件：

- `index.html`：包含脚本、样式及需要的内嵌资源，不依赖原站接口。
- `build-report.json`：构建模式、来源模块、文件哈希及未执行的验收项。

不会生成 ZIP、截图、DesignSpec 或 Figma 文件，也不会覆盖既有输出。需要更新时指定另一个新目录。此入口不改变旧的 `feedback-reference` 命令或其历史产物。

全部参数先校验，再加载构建器和读取源码。常见错误为固定代码，不回显输入值：

- `FIDELITY_DEVICE_CONFIRMATION_REQUIRED`：缺少显式端型选择。
- `FIDELITY_DESKTOP_ONLY`：端型不是 `desktop`，或缺少 `--device` 的值。
- `FIDELITY_SOURCE_REQUIRED` / `FIDELITY_OUTPUT_REQUIRED`：缺少源码或输出目录参数。
- `FIDELITY_ARGUMENTS_INVALID`：未知、重复、位置参数或其他非法参数。
- `FIDELITY_SOURCE_UNAVAILABLE`：源码路径或构建入口无法访问；检查 `--source` 是否为完整后台源码根目录。
- `FIDELITY_OUTPUT_EXISTS`：输出已存在，保持原文件并停止。
- `FIDELITY_OUTPUT_OUTSIDE_WORKSPACE`：输出超出本仓库。
- `FIDELITY_STYLE_TOOLCHAIN_UNAVAILABLE` / `FIDELITY_IMPORT_UNRESOLVED`：当前源码依赖缺失或结构与适配目标不同。

## 当前源码与依赖边界

此适配器针对本次实际 `cs_admin-client` 页面闭包，不是任意 React 项目的通用转换器。已编译核对的源码依赖包括 React 18.2、Ant Design 5.7.3、Pro Components 2.8.10、Ant Design Icons 5.6.1，以及详情使用的 `antd-mobile` 组件。后者是原 PC 详情的内部依赖，不代表生成了移动端。

构建复用原源码已安装的依赖，使用本仓库现有 esbuild。原 `App.less` 通过已安装的 Less 编译器处理；Tailwind 3.4.14 仅扫描本次实际组件闭包及独立入口。源码 Tailwind 配置只提取支持的静态数据，不执行配置文件。依赖升级、缺失或页面结构变化可能需要重新适配，不应仅凭本次构建记录推断未来版本可用。

构建器不导入原 `App`、应用入口、Rsbuild 配置、动态路由注册或环境文件，不注入原应用环境变量。未知或禁止的导入、运行时环境访问及直接网络调用会拒绝构建。诊断只报告固定错误；出现拒绝时应审查必要依赖，不能通过放开整个原应用初始化来绕过边界。

## Mock 与隐私

原服务适配与数据标准化继续复用，`@monorepo/network` 和 `@monorepo/utils` 在模块边界替换为本地实现。所有业务响应来自新建的合成 fixture；认领、指派、回复、客服状态等只修改当前页面内存，刷新重置。未知 endpoint 明确拒绝，不回退到真实接口。

详情中的敏感图片审核入口连接原图片审核页面组件，以本地 MemoryRouter 保留反馈列表状态并展示审核标签页。该页面原服务涉及鉴权和环境信息，因此在读取之前按精确路径替换为本地 service；图片、任务、日志、审核结果均为合成数据。审核、删除和补录 mock 仅作用于内存，源 UI 没有可见入口的动作不会补造按钮。

## 编译副本中的局部修复

真实交互测试发现四类原源码缺陷。`source-repairs.mjs` 只在内存编译副本中修复，原客服源码不写入：

- 批量回复拒绝纯空格，保留原必填错误文案；捕获表单校验的预期 rejection。
- 回复 API 失败显示错误提示，保留草稿、弹窗和勾选，可重试。
- 从详情前往图片审核时关闭来源抽屉，防止旧 portal 在审核结束后遮挡列表。
- 详情沟通记录在请求前即时占用页码，阻止 React 提交间隙重复请求旧页、重复在途请求和末页之后的请求；成功后同步推进游标，失败不推进，允许重试同一页。关闭、切换工单或刷新首屏后，版本隔离继续阻止旧响应回写当前历史记录。

修复具有精确文件与代码形状边界，支持原文件 CRLF；形状变化会以 `FIDELITY_SOURCE_REPAIR_SHAPE_CHANGED` 停止构建。`build-report.json.localUIRepairs` 记录实际使用的修复。不能据此声称原系统本身已经修好。认领请求失败时，原页面 catch 没有错误提示；本地适配仍沿用这一行为，不修改记录、不显示成功提示，并允许重试。

本入口不读取登录浏览器、Cookie、storage、真实接口响应或真实业务记录。它也不是通用脱敏器：若接入的源码自身含有业务样本或敏感常量，须在接入前审查；不能把真实数据放进 fixture，再把「使用了 mock」当作已经脱敏。

输出使用禁止连接的 CSP、精确脚本哈希和样式 nonce；需要的本地静态图片和字体资源会内嵌，合成图片直接使用 data URL。本次页面主要依赖 Windows 系统字体 Segoe UI 与 Microsoft YaHei，没有把系统字体文件打包；其他操作系统的字体回退效果须重新验证。原 AntD 静态提示会建立独立上下文，构建器为可信运行时代码创建的 `style` 元素补同一 nonce。该兼容不会开放 `unsafe-inline` 或真实网络传输。CSP 与运行时拦截属于导出物防护，不能替代输入源码审查。

## 源码页面到原生 Figma 的模块边界

以下模块由本地 Agent 编排，不会被上述 HTML 构建命令自动执行：

- `capture.mjs` 的 `captureFeedbackDOM` 在本地 mock 页面中提取可见 DOM、文字行、控件内容、CSS 盒、完整 SVG、伪元素、裁剪和绘制顺序。它拒绝非本地页面、非 mock 页面及带鉴权采集标记的输入。截图只作为视觉验收证据，不作为整页图片导入 Figma。
- `font-map.mjs` 根据已确认可用的 Windows 字体生成逐段字体映射。中文、拉丁文字和 Emoji 分段保留；缺少已确认字体时停止，不静默改成其他字体。
- `library.mjs` 从捕获集合规划 RGBA 颜色变量和 SVG 组件，再用公共 Plugin API 创建新的、有明确归属的库。同 RGB、不同 alpha 分别建变量，alpha 保留原数值精度；图层自身的 opacity 独立保留，不提前乘进颜色变量。按钮组件模板尚未实现。
- `native-import.mjs` 将捕获转换为可编辑文字、CSS 形状和完整 SVG；命中的 SVG 使用库组件实例，并绑定已验证的颜色变量。简单单标签元素使用测量得到的 Auto Layout；其他布局仍以测量位置重建，不能宣称已恢复完整响应式约束。
- `native-chrome.mjs` 为已导入画面补充截图与 DOM 共同证明的浏览器滚动条及文本域缩放手柄。只接受窄范围装饰区域，生成可编辑矩形，不追踪正文、整页截图或猜测隐藏滚动条；补层是外观还原，不能作为真实滚动或拖动行为的证据。
- `interactions.mjs` 将真实可见控件映射到已经捕获的目标帧，再为这些节点设置原型连线。隐藏控件、缺失目标和未捕获的分支会记为 unmatched，不创建无依据的热区。输入预设只演示已捕获状态；任意输入、业务校验和数据修改由本地 HTML 执行。
- `interaction-extensions.mjs` 为本次已冻结的 41 状态、125 条连线及 5 个入口提供独立的追加记录，不重写原操作。构建阶段校验真实 mock capture、可见区域、祖先裁剪和禁用状态；存在活动弹窗时拒绝其背景控件。调用方仍须另行证明工单实体、选择集合与业务上下文一致，不能只按相同文案连接。

恢复 Figma 浏览器会话后，须重新检查 `listAvailableFontsAsync()` 是否包含已确认的字体及样式，并回读原生文字的 `hasMissingFont`。本机装有字体不代表网页版已连接字体服务；已有 FigmaAgent 未运行时，重新连接服务并正常刷新文件，再执行原生审计。若仅缺字体标志发生变化，也必须保留失败记录，不能忽略该字段、改用替代字体或重写原快照哈希来通过检查。字体服务的连接和重启方式见 [Figma 官方排查说明](https://help.figma.com/hc/en-us/articles/32801027692183-Troubleshoot-the-Figma-Font-installer)。

使用本项目自有公共 Plugin UI 执行器时，调用适配层须为每种成功或失败的返回结果添加 `FEEDBACK_` 开头的 `tag`，并完整保留产品函数的结果字段。原生 importer 本身没有该 UI 标记；只编译脚本不能证明回包格式兼容，必须执行实际编译后的 audit、export 及失败审计脚本进行验证。没有收到符合契约的回执时保留未知状态，不自动重放操作。

追加连线需显式提供原计划及其完成记录哈希、所有获准状态的 capture 和当前原生记录哈希，再以全新 operation key 执行。运行时先保存原 125 条反应的原始 JSON、原命名空间字节及完整入口顺序，默认只为原反应为空的获准节点写入 `ON_CLICK → NAVIGATE`。每批最多 20 个单位。默认模式的最后一个单位仅清理本次写入实际产生并已记录的 `Flow N` 入口；原 5 个入口保持同名同序。未知入口、已有反应、漂移或不确定写入会保留 pending 和 intent，不能自动重试。

需复现自动消失提示时，可显式提供 `trigger: { type: 'AFTER_TIMEOUT', timeout: 3000 }`。`timeout` 使用整数毫秒，通用接口限定为 1 至 60000；未提供 trigger 的旧计划字节和默认行为不变。定时来源只能是获准的顶层 `Scene`，须同时匹配 capture 根、原生 Scene 记录、归属和页面父节点。capture 根到内部 `Source bounds` 的映射不能替代 Scene 身份证明。定时参数和目标上下文需要调用方提供来源证据，不能凭截图猜测时长，也不能把业务修改后的提示直接连接到修改前的数据画面。真实自动触发、最终画面及动画效果仍需在 Present 中另行验收。

宿主自动入口编号无法预先证明时，可显式选择 `flowStaging.strategy: 'EXPLICIT_SOURCE_ROOTS'`，与自动编号策略互斥。调用方须为所有尚无原入口的新增连线来源画面，提供完整、无重复的根节点与绑定本次 operation key 的临时名称。该模式以暂存入口、逐条连线、清理入口的顺序执行，共 `新增连线数 + 2` 个单位；仅清理记录中的临时入口，未知增删、改名或重排均停止。每次异步回读后核对入口、原生记录和热点，最后以无异步间隔的检查再次核对全部旧、新热点。

暂存模式还保留本次命名空间的完整字节见证。header、chunk、intent 或新增未知键发生外部变化时，返回 `FAILED/pending` 及 `ledgerSaved: false`，保留未知字节，不通过异常处理覆盖它们。本地替身测试只证明这些拒绝路径和状态推进，不能证明实际宿主行为或 Present 已通过。

追加审计将原有路径和新增路径分别计数。它核对完整原生记录字节、来源映射与节点归属，不执行整树视觉快照或 Present 点击；这些仍须单独验证。该模块尚未由上述 HTML CLI 自动调用，也没有把 Figma 的预设连线变成任意文本输入或可执行业务逻辑。

勾选连线还须证明真实行实体、已选集合、勾选汇总数量及两端表单和表格上下文一致。单击一行不能直接跳到选中两行。当前补充采集的 `selected-one` 仅选中合成工单 `910001`，用于连接默认列表、再勾选 `910007` 后的双选状态及对应反向操作；未采集的一条回复弹窗或其他选择组合仍记为 unmatched。源码事件存在、目标帧存在或图层已经可编辑，都不能单独证明该原型路径可用。

规划器保留默认列表主流程，并为不能从主流程到达的已捕获第二页、多关联、批量回复失败、横向滚动末端及固定列状态提供独立场景入口。当前这些状态以四个附加 Flow 覆盖，已有真实点击连线不变。它们供用户通过 Figma Present 的流程菜单选择预设场景，不代表已经恢复视口外分页控件、列设置 hover、真实滚动或故障注入；不能把场景入口计作原系统页面中的点击交互。

连线验收的分母是冻结计划中已规划的路径，不能用「计划路径全部通过」代替「原系统全部交互已覆盖」。需要另外记录未连线的可见控件、未捕获的上下文和输入预设数量；同页其他行、其他下拉选项、日期单元格和列拖动柄不会自动获得已演示路径的能力。原始 `unmatched` 还包含遮罩背景、标签和重复项，也可能漏掉非语义控件，应按当前可交互区域和交互家族复核。HTML 中实际运行的 mock 查询、校验和业务流程与 Figma 中的预设点击导航分别验收。

真实 Figma 还可能在 `setReactionsAsync` 后自动创建流程入口。连线适配器在首写前保存 `flowBaseline`，由调用方明确提供已核实的 `hostAutoFlowPolicy` 后，才记录单次反应写入所产生的一个入口：根节点必须是本次反应所属的已授权画面，名称必须符合已确认的连续序号。每步、续批和审计都比较完整入口清单，未知新增、改名、删除或重排均停止。最终仅用计划入口替换已记录的自动入口，保留基线中其他根的入口。

较早的部分完成记录若缺少 `flowBaseline`、`hostGeneratedFlows` 或 `hostAutoFlowPolicy`，会拒绝自动续写。必须先独立核对原记录字节、已写反应、未写节点、实际入口及节点归属，再显式迁移这些元数据；迁移不能重放已有反应，也不能凭当前入口清单默默建立基线。本次已核实的主机名称为英文 `Flow ` 加从 1 开始的序号，其他命名方式尚未纳入策略。

这些函数不建立 Figma 连接。调用方必须先核实用户授权的文件和页面；本次库适配器将页面范围固定为 `23:2`，连线适配器则严格绑定调用方指定的页面及其已完成的原生导入记录。调用方仍须核实授权，不能把适配器当作任意 Figma 文件的通用导入器。传入 `figma` 时只使用公共 Plugin API，不能通过网页私有运行时接口写入。

网页端桥接应按真实 `design/<fileKey>` 路径段核对文件，不能用整个 URL 的子串匹配。自有 Plugin UI 应识别唯一控件及其归属标记，通过公开消息接口指定实际插件 ID，并校验回复来源、祖先窗口和请求 ID；捕获与回执不应再转发给无关的第三方插件网页。这些消息边界遵循 [Figma 的公开 UI 通信说明](https://developers.figma.com/docs/plugins/creating-ui/)。控制面板的请求已完成只表示收到了结果，业务函数返回 `FAILED` 或 `pending` 时仍须停止。

浏览器桥接须区分本地等待超时与执行终止。[CDP 协议](https://raw.githubusercontent.com/ChromeDevTools/devtools-protocol/master/json/js_protocol.json) 中 `Runtime.evaluate.timeout` 会终止执行，不应用它轮询正在执行公共 Plugin API 的页面。调用方在发送前和收到终态后核对文件路径；等待期间仅从已验证的自有 Plugin UI 上下文读取同一请求的回执。被动读取的传输超时可以在总等待预算内继续观察，不重发写操作；上下文丢失、控制权变化、结果未知或预算耗尽时保持未结算状态，先独立回查。

原生导入、库创建与连线分别保存有哈希的操作记录，并返回实际创建或修改的节点 ID。每次续写都核对输入、资源归属及已有节点；pending 或漂移会停止，不能把失败请求重新发送来碰运气。新导入的节点快照以 SHA256 保存，校验属性保持不变；旧完整快照仍可审计。`scenePosition` 与 `libraryRefs` 都属于续写范围，不能在同一操作中更换。

库创建和原生导入在续批时固定已有节点的期望证据，不能因字体加载、节点读取或内部异步函数返回期间发生外部编辑，就把它们收为新快照。追加前先核对受影响节点，仅接纳本次同步追加产生的精确子节点迁移及 Auto Layout 几何变化，名称、填充等属性继续严格核对。新导入文字在字体等待和内部异步返回期间也保留临时证据。首写前发现漂移时保持原记录；写入中发现漂移时停止，保留 pending 或未知状态及已有检查点，不用失败分支重建旧证据。该保护不会锁住编辑器或自动回滚用户修改，真实宿主行为仍须另行验收。

浏览器装饰补层使用独立命名空间。先只读预检，锁定原生操作记录的现场哈希，再执行写入；原 header、全部 chunk 字节及受影响父节点快照先完整备份。补层仅追加到已核实的非 Auto Layout `Source bounds`，保留原 children 顺序及其他属性，原生记录只更新这些父节点因新增 children 而改变的快照哈希。创建后同步核对计划属性，几何和 RGB 仅允许 `1e-6` 宿主浮点误差；首次异步读取前冻结快照，回读不能将外部编辑采纳为期望值。失败保留 intent 和已创建节点清单，不自动重放。

遮罩下的滚动条必须来自同几何、同滚动位置的未遮罩 mock 参考，并证明已有纯色遮罩的合成关系。原参考 palette 保持不变；仅在确认同一浏览器装饰身份时，允许最多 `0.001` 比例像素、每通道最多 1 级的遮罩量化残差，逐点记录。这不是最终 PNG 验收容差；真实导出仍采用严格像素差异指标，未知遮罩、部分遮挡、真实阴影混合或无法证明的区域不补造。

阴影包围框的保守估算可能覆盖实际不受阴影影响的滚动条。只有目标与同几何、同滚动状态的未遮罩 mock 参考在整个 ROI 上逐 RGBA 严格相等，且该参考本身能通过无 witness 的独立规划时，才记录 `shadowWitnessProof` 并排除这一包围框误报，不关闭阴影检查。遇到彩色圆角边框时，缩小 ROI 或用稳定 `partId` 将手柄拆成互不重叠的窄部件，不能将边框或正文一并追踪；同一父节点的原快照只备份一次，全部部件完成后更新一次最终快照。

新增装饰矩形显式写入 `paint.color.sourceColor`，以 `SRGB` 保存截图色值的作者空间，并回读作者空间、RGB、opacity 和几何；数值容差仍为 `1e-6`，不支持或丢失作者空间时停止。实际宿主中，只写旧 RGB 字段可能得到与输入不同的投影浮点值，即使 8 位 PNG 像素相同也不能绕过写入检查。既有补层继续按其冻结快照审计，不为更新作者空间而重写已验收节点。导出的严格像素对比仍单独执行，不能由颜色属性回读代替。

本次实际回读发现，删除组件或变量集合后，同一插件会话仍可能按 ID 返回旧对象。应结合当前顶层归属、本地资源枚举和变量清单核对；必要时关闭已停止的插件，重新载入同一授权文件后做独立只读回查。不能因旧对象仍可查询就重复删除，也不能仅凭一次列表消失就把未核实的操作记录改为完成。

变量库使用 `/2` 数据合同和独立 v2 命名空间。实际 Figma API 验证发现，颜色别名解析会覆盖 paint 的 alpha，因此不能把半透明 paint 绑定到 alpha=1 的 RGB 变量。绑定函数的返回值也不足以证明最终效果；本实现给节点赋值后回读实际变量 ID、RGB 和 alpha，允许 `1e-6` 的原生浮点误差，匹配缺失、歧义或失真均停止。旧 `/1` RGB 库不能混入新导入。

浏览器文字紧框与 Figma 原生文字 advance 不能互换。本次实际测得同字体的 `demo-openid-001` 在浏览器约为 112.98px，在 Figma 自然布局需要 114px。浏览器已经确定的每个逻辑行，在有完整 DOM Range、连续字符偏移、同基线矩形、水平从左向右及无旋转变换证据时使用原生自然宽度，避免 Figma 再次换行；`normal` 与 `pre-wrap` 的软换行仍沿用浏览器实际分行。保留原行位置、CSS 容器和裁剪范围，不缩字号、改字距或放宽真实裁剪来隐藏缺字。证据不完整、控制字符或无法证明的空白折叠均保留原宽度策略；Auto Layout 标签和有证据的省略号也维持其单独策略。

输入框与文本域的合成文字探针需要单独恢复原生控件的内容裁切，不能只沿用 DOM 祖先的 CSS overflow。导入器按已采集的 `controlText.contentRect` 建立专用裁切层，并减去记录的 `scroll.left/top`；保留完整可编辑文字及原字号，不把长值截成字符串。内容区、探针来源、矩形交叉证据或滚动记录缺失时，在写入前拒绝；整数 client 尺寸与小数 DOMRect 的边缘核对允许最多半像素舍入差，不修改采集尺寸。此修复独立于上述 DOM 自然行策略。

透明抽屉包装层的 CSS 阴影还需要宿主适配：Figma 无填充或零 alpha 形状不能投影。仅当后绘制的直接内容层有同边界、同圆角、完全不透明且覆盖未被裁掉的证据时，导入器创建独立命名的阴影载体，并记录覆盖来源；原透明层不改色。条件不满足时保留警告，不能任意补白底。手工编辑内容层后若改变覆盖关系，需要重新核对该辅助层。

Figma 的结构审计、PNG 视觉对比和 Present 点击验证是三个独立结果。即使节点与变量均通过审计，字体栅格、浏览器原生滚动条、未实现的布局约束和缺失连线仍可能影响还原。代表状态的数量不等于所有输入组合或所有权限分支已经覆盖。
