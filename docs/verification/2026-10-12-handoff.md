## 剩余验收执行顺序

1. **实际独立回导**：在 Figma 将保存的 .fig 导入一个新文件，记录实际导入时间、文件地址、sourceSha256 和观察证据；新 fileKey 必须与原文件不同。不能通过重新生成一套节点代替导入。
2. **定位复制后的 v10**：读取新文件的页面与 root ID，选择复制后的 v10 页，保留同一 specId、specSignature 和 runId 作为回导对照。不要沿用原 `55:88` 或凭名称猜 ID。
3. **重新连接与授权**：创建新的本机 session 配置，fileIdentity 指向新文件，specPath 指向已固定的 v10 规格，outDir 使用新的证据目录。先 status/document，再按实际 clientId、page/root 签发精确 read/export 授权。旧授权可能过期或绑定旧客户端，不能复用。配对和授权的细节按[启动指南](../guide/getting-started.md)执行。
4. **只读完整审计**：新作用域审计须收齐稳定分页，记录 `reimport-audit.json`。遇到资源、所有权、签名或用户编辑冲突时保留真实错误；不以 apply/reconcile 修复回导对象来伪造一致。新文件 ID 可变化，稳定 key 和结构、资源、交互仍须一致。
5. **回导画面与历史保真分别核验**：从回导页导出 55 场景 PNG，与原 `original-png` 做零像素比较；再对其余 50 场景做历史 ArchiveLens 画面视觉复核。原生回导像素一致与历史应用保真是两个不同门禁；已批准的字体差异须明确记录，不用放宽回导容差掩盖缺陷。
6. **真实 Present**：执行默认尺寸路线、紧凑尺寸路线、计时跳转及两尺寸滚动；每项记录真实步骤、观察时间、结果和截图。739 反应结构一致不等于每条交互已经播放验收。
7. **最终验证和解包重验**：填齐实际导入、审计、视觉与 Present 记录，再运行交付验证器。整体 PASS 后解包 delivery.zip，使用包内 manifest 在新的空目录重验，确认不依赖原工作目录。
